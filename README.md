# Minidoracat Vehicle Manager for B42

提供車輛綁定、所有權保護、個人與陣營車隊管理，以及 MiniMap 追蹤與 Economy 租賃整合的車輛管理系統

Project Zomboid Build 42 MOD。

## 發布狀態

已發布到 Steam Workshop（ID：[3813972279](https://steamcommunity.com/sharedfiles/filedetails/?id=3813972279)）。綁定、保護、分享、車隊視窗、小地圖追蹤、MVCK 移轉與拖車相容都已通過本機多人實機測試。

## 功能

- 綁定車輛（綁帳號，角色死亡不失去），每人上限由伺服器設定
- 伺服器權威保護：未授權者的開關門、解鎖、上車、發動、加油抽油、放氣、裝拆零件、修理、砸窗、拖曳一律拒絕，並把車況推回原樣
- 車輛指令防火牆：原版與 Autotsar（tsarslib，含 SVU3 調校零件）、rSemiTruck／W900、damnlib（KI5）、Vehicle Repair Overhaul 直接修改車輛的伺服器指令，在它們處理之前先檢查權限與距離（與 MOD 載入順序無關）
- Vehicle Repair Overhaul 相容：別人綁定的車不能用它的「回收車輛」整台拆掉（排入時就擋下，不會開始拆解）；它的零件修理、引擎重組、暖氣與警示燈修理要「安裝修理」權限，從車外打開警示燈或警笛要「駕駛」權限；車主拆自己綁定的車要先解除綁定
- 車上容器依權限開放：後車廂、車斗、拖車與模組車貨箱需要「後車廂」權限，座位與置物箱需要「搭乘」權限，沒權限就不出現在物品欄
- 車主虛擬鑰匙（可關閉）
- 分享給指定玩家或陣營，逐項授權（「全選」一次打開全部權限）；也可以公開給所有人（只限搭乘、駕駛、後車廂、加油、安裝修理）。車主權限（改名、分享、解除、轉讓）不可分享
- 陣營改名、解散或換領袖時，分享給這個陣營的車一起暫停並通知車主；成員在「分享給我」看得到哪個陣營暫停了幾台、被擋時提示要車主恢復；換領袖時車主在「我的車」最上面勾選後一鍵恢復，權限照原本的、改綁到新領袖（改名或解散就重新分享給陣營）。領袖在原版陣營視窗「更改擁有者」時先提醒會暫停幾台車（只是提醒，不替車主恢復）
- 右鍵看得到車主：別人的車在右鍵「車輛管理」第一列寫「車主：帳號」，分享給你或公開的車下一列寫你可以做什麼
- 車主長期沒上線（預設 30 天，伺服器關機時間不算）自動解除綁定；車隊視窗顯示「保留到」日期
- 車隊視窗：我的車、分享給我、紀錄（車主通知）、管理員頁（依玩家列出已綁定數與上限，含登入過但還沒有車的玩家；展開看車、調整個人基本名額、勾選多位玩家批次設定或恢復預設、修改所有玩家預設名額）
- 管理員越權開關：管理員預設跟一般玩家一樣不能用別人的車；在管理頁開啟後才能操作任何車，每次越權寫入稽核記錄，開啟期間方向盤按鈕（家族工具列裡的入口）紅框、車隊視窗頁尾提示；重新登入或伺服器重啟自動關閉
- 鍵盤與手把操作：Tab 在分頁、名額、搜尋框、清單與按鈕之間移動，清單上下鍵移動、管理頁左右鍵展開／收合玩家；手把玩家開窗即接手（方向鍵、A 確認、B 返回、LB／RB 切頁）
- 選用 MiniMap：自己的車與有「查看位置」權限的分享車顯示在地圖上；每台車可自訂圖示、顏色與大小（只存本機）。MiniMap 齒輪「地圖顯示設定」的「車輛管理」分類有「綁定車輛」圖層（小地圖與世界地圖各自開關車標、調整大小、分開設定兩邊是否顯示車名）與「開啟車隊視窗」按鈕；舊版 MiniMap 只有「小地圖顯示車名」勾選框
- 從 Mysterious Vehicle Claim Key 移轉既有綁定（MVCK 允許陣營共用時一併開啟陣營分享；MVCK 的公開權限轉成「公開給所有人」）
- 拖車相容：rSemiTruck 多槽拖車與 Autotsar 拖吊裝卸需要「拖曳」權限，卸下拖車上的車也要對那台車有「拖曳」權限（公用拖車也一樣）；車被裝上拖車時紀錄保留（車隊視窗顯示「暫時不在世界上」），卸下後即使換了內部編號也自動恢復綁定；已綁定的 Autotsar 拖吊車裝過車後仍維持綁定；載著已綁定車的拖車或拖吊車，本身不能再被裝上另一台拖車
- 載具也要綁定：已綁定的車只能裝上已綁定的拖車或拖吊車（車主與管理員也一樣），拖車也佔一個綁定名額；綁定確認視窗顯示目前已用名額，能裝車的載具另有提醒；拖車上還載著已綁定的車時不能解除綁定（包括「車已遺失，解除綁定」），先卸下
- 防破壞：車上沒有車主或被分享的人時，武器（近戰、槍）打不壞綁定的車；伺服器每 10 秒把損傷補回、被打破的車窗換新並清掉碎玻璃。有人上車或被拖曳時暫停，下車後重新開始。攻擊者會看到「這台車有防破壞，武器打不壞」；有人用武器打車（近戰或開槍，打到哪裡都算）時車主會收到通知，並記在車隊視窗的「紀錄」分頁（不在線也會記下）；通知由攻擊者的遊戲回報，改過客戶端的人可能不會觸發。管理員可設定為關閉、所有綁定的車（預設）或依防破壞名額（見下方「防破壞」）
- 車隊清單直接看出防破壞：有防破壞的車在狀態列右側顯示盾牌圖示與「防破壞」，不必打開詳情
- 車主通知紀錄：車隊視窗的「紀錄」分頁記下有人用武器打你的車（誰、哪台、有沒有被防破壞擋下）、防破壞修復損傷、防破壞名額減少而暫停、租用名額的鎖定／解鎖／解除綁定；不在線時也照記。登入時若有離線期間的通知，會提示「你不在線時有 N 則車隊通知」，方向盤按鈕與分頁名稱顯示未讀數，打開分頁就算已讀。同一個人 10 分鐘內反覆攻擊同一台車合併成一則並顯示次數；保留 30 天、每人最多 50 則，只有自己看得到
- 車上收音機的耳機裝拆需要「後車廂」權限

**保護範圍的誠實說明**：保護的是一般玩家操作。開著防破壞的車停放時不怕武器；有人在車上、被拖曳時，或沒有防破壞的車，武器、殭屍、碰撞照原版損壞（停著沒人的車本來就不會被殭屍攻擊、被別人開車撞也不受損）。改機客戶端繞過武器的直接傷害只能在下一輪補回（最多約 10 秒）；油、電池電量與車上物品不會補回。改機客戶端可能短暫坐上座位，伺服器巡查約一秒內發現並處置（可設定為只記錄或移出車外）。車上容器列不列出是玩家端判定（伺服器搬物品時不檢查門鎖與權限），改過客戶端的人仍可能拿到裡面的物品，與原版鎖車同級；開關後車廂門仍由伺服器擋。多人伺服器上以分割畫面加入的第 2～4 位玩家沒有車輛管理身分：不能綁定或使用分享，任何已綁定的車對他們都拒絕。Steam 伺服器上，玩家要用綁定的 Steam 帳號登入才算是那個帳號（管理員匯入白名單後啟用，見下方「玩家身分」）；no-steam 伺服器沒有 Steam 帳號可比對，照舊以帳號名稱判定。

**拖車與其他 MOD 的保護限度**：本 MOD 只保證列入防火牆或動作防護的指令（原版車輛指令、Autotsar／SVU3、rSemiTruck／W900、damnlib、Vehicle Repair Overhaul）；其他 MOD 自己的伺服器指令不宣稱受保護。rSemiTruck 多槽拖車的裝卸現在由本 MOD 的伺服器檢查擋下；本 MOD 另在車身寫入它認得的車主與可拖曳名單（只在 rSemiTruck 啟用時寫），這份名單所有玩家端都讀得到、也可被改過的客戶端竄改，本 MOD 自己的授權不看它；rSemiTruck 自己的檢查以玩家名稱認人，伺服器不需要分割畫面時建議關閉 `AllowCoop`。卸車時本 MOD 依「這台車裝在哪台拖車上」的記錄，要求對那台車也有拖曳權限；本版之前就已裝在拖車上的車沒有這筆記錄，卸下時只檢查拖車本身。W900 貨櫃裝上貨櫃拖車再卸下後，是一個新的、沒有綁定的貨櫃（rSemiTruck 只搬物品與外觀），原本的綁定不會跟過去，要保護就重新綁定。分享對象只有「駕駛」權限時，駕駛 KI5 裝甲車的裝甲耐久同步會被伺服器擋下（需要「安裝與修理零件」權限）；W900 一般的裝甲自動補回照常，防撞桿替引擎吸收傷害的補回同樣需要「安裝與修理零件」。不在防火牆範圍的：車上容器的物品搬移（玩家端判定）、原版的調整頭燈照射角度（只改燈光方向）、座位上的操作（開燈、喇叭、後車廂鎖等，原版只讓車上的人操作，上車本身受保護）。

已加入選用 Economy 通用權益整合：買斷與定期租用綁定名額、防破壞名額，付款就能用。不是買車、不是每台車的保護費；道具名額券尚未實作。

## 依賴

- **必要**：`MinidoracatUIFor42`（介面框架，需 API rev 9 以上：視窗、頁籤、輸入框、按鈕、開關、確認框、色盤、滑桿與車型圖示都來自框架；鍵盤與手把操作需要 rev 10，較舊版本照常用滑鼠；付費名額設定視窗需要 rev 11）。
- **選用**：`MinidoracatMiniMapFor42`（地圖追蹤：marker API v1 起上圖，v2 起套用每台車自訂大小與圓底外環；settings API 5 以上且 marker API 3 以上時，設定裡才有「綁定車輛」圖層與「開啟車隊視窗」按鈕，較舊但有 settings API 的版本保留「小地圖顯示車名」勾選框）、`MinidoracatEconomyFor42`（付費名額，需支援「方案由來源 MOD 設定」（`setPlan` 能力）的新版；較舊的 Economy 視為不支援）。沒裝時免費核心與既有車輛保護照常運作。

## 付費名額（選用 Economy）

- 需在多人專用伺服器同時安裝相容的 Economy；單人只使用免費核心。
- 兩種名額各自販售、各自設定：**綁定名額**（車隊視窗右上「綁定名額」）與**防破壞名額**（防破壞設為「依防破壞名額」時，車輛詳情的「防破壞名額」）。
- **付款就能用**：名額視窗可以看基本、買斷、租用名額，一次買斷多個，或租用多張各自到期、各自續租與自動續租的租約。付款當下名額就生效；伺服器崩潰沒存檔時，付款與名額一起回到上次存檔。付款前會顯示伺服器報價，結果未知時只查原單，不會再次扣款。
- **方案由本 MOD 管**：價格（租金是每個名額每期）、幣別、買斷上限、每位玩家租用上限、租期、寬限、提醒、是否允許自動續租與兩種販售的開關。Economy 只管錢包、幣別與收費流程，它的管理台「整合方案」頁是唯讀總覽。
- **設定檔** `Zomboid/Lua/MinidoracatVehicleManager/<伺服器名>/paid-slots.json`（綁定名額）與同資料夾的 `guard-slots.json`（防破壞名額），格式相同：伺服器每 5 秒讀一次，改完存檔就生效，不用重啟。第一次啟動時自動建立（兩種販售預設關閉）。鍵名固定，不可多也不可少（`reason` 選填，會寫進 Economy 的修改紀錄）；數值範圍由 Economy 檢查：

```json
{
  "buy":  { "enabled": false, "price": 1000, "currency": "survivor", "limit": 10 },
  "rent": { "enabled": false, "price": 250, "currency": "survivor", "limit": 5, "days": 7,
            "graceHours": 24, "reminderHours": 24, "autoRenew": true },
  "reason": "..."
}
```

- **狀態檔** 同資料夾 `paid-slots.status.json`／`guard-slots.status.json`：每次處理後整份覆寫，外部程式或 AI 改完設定檔讀它就知道結果。`state` 是 `ok`／`error`／`economy_unavailable`，`source` 是 `file`（設定檔）／`admin`（遊戲內）／`created`（自動建立），另有 `revision`、`error`（錯誤碼）、`field`（出錯的鍵，例如 `rent.price`）、`at`（UTC 時間）、`economy`（整合狀態）。設定檔有錯時方案維持原樣，同一份錯誤內容不重複處理；Economy 不在或不支援時只在開機寫一次 `economy_unavailable`，不建也不讀設定檔。
- **遊戲內設定**：管理員在車隊視窗管理頁的「付費名額」列（「付費綁定名額設定」；依防破壞名額時另有「付費防破壞名額設定」）或名額視窗頁尾開設定視窗，改完填寫原因後套用；套用成功會寫回同一份設定檔（含原因），並寫入稽核記錄 `ADMIN_PAID_SLOTS`。設定檔寫不進去時會提示：方案已生效，但伺服器重啟後會用設定檔的舊值。編輯期間別人改過方案時，視窗會載入最新值（自己改過的欄位保留）再讓你確認，不會蓋掉對方的修改。
- 自動續租預設關閉，需玩家明示同意。租金、幣別或天數改變時，該張租約的自動續租暫停到玩家重新同意，改回原值就恢復。
- 名額上限＝基本名額（有管理員個人設定時取該值）＋可用的付費名額。退款或 Economy 查詢失敗不會解除已綁定車；超額時只禁止新增。
- **租用的綁定名額到期**：租約到期後進入寬限期（設定的「寬限時數」），寬限中的名額不能再拿來綁新車。寬限期間超出名額的車從最晚綁定的開始**鎖定**：車主與分享者都不能使用（陌生人照樣擋），車主仍可解除綁定、改名或調整分享；續租、或解除其他車讓名額夠用，就立即解鎖。寬限結束、租約從 Economy 移除後仍超出名額，鎖定的車會**解除綁定**（稽核記錄 `STATE … RENT_EXPIRED`，車隊視窗寫「租用名額到期，已解除綁定」）。鎖定、解鎖、解除時車主都會收到通知（不在線也記在「紀錄」分頁）；讀不到 Economy 時一律不動。管理員調低名額這類不是租約造成的超額不會鎖定。
- **租用的防破壞名額到期**：寬限結束後，超出防破壞名額的車暫停防破壞（沒手動選過的車先暫停，再來是最晚勾選的），車輛照常綁定；名額恢復後自動繼續。
- 付費財務權益存在 Economy 的世界資料，不另在車輛帳本加一份購買計數。

## 防破壞（伺服器管理員）

- **模式**就是沙盒選項「防破壞」（`ParkedGuard`）：`1` 關閉、`2` 所有綁定的車（預設）、`3` 依防破壞名額。管理頁的「防破壞」列可以直接切換（確認後立刻寫進伺服器沙盒設定並同步給線上玩家，稽核記錄 `ADMIN_GUARD MODE`）；用原版沙盒設定改，約一分鐘內生效。不需要 Economy。
- **依防破壞名額**：每位玩家可防破壞的車數＝「每位玩家防破壞名額」（沙盒 `GuardSlotsPerPlayer`，0–20，預設 1；管理頁常駐欄位同步）＋管理員為個別玩家設定的防破壞名額（管理頁玩家詳情，0–100，優先於預設）＋付費防破壞名額（有 Economy 時）。名額自動用在最早綁定的車，從「所有綁定的車」切過來、綁新車、買到名額都不必重新設定；車主在車輛詳情勾選「防破壞」就把名額移到那台（車主勾選的車排在沒選過的前面），取消勾選就讓給下一台、之後也不會自動排回。名額減少時沒選過的車先讓出，再來是最晚勾選的；名額回來自動恢復，車主會收到通知。
- **原理與限制**：車上沒有車主或被分享的人時，伺服器把零件的武器抗傷係數拉高，武器打不出傷害；每 10 秒把低於停放時基準的耐久補回、被打破的車窗換上同型新玻璃並清掉車底碎玻璃（稽核記錄 `GUARD_RESTORE`）。有人上車、被拖曳時暫停，下車後以當下車況為新基準（開車造成的損傷不補）。車主或有權限的人自己拆裝、砸窗不會被補回。油、電池電量、車上物品與不見的其他零件不補。其他 MOD 在停放期間直接降低零件耐久也會被補回。

## 綁定名額（伺服器管理員）

- **所有玩家預設名額**就是沙盒選項「每位玩家可綁定車輛數」（0–20）。管理頁常駐欄位與沙盒選項是同一個值：在管理頁改，伺服器立刻寫進 `Server/<伺服器名>_SandboxVars.lua`（存檔失敗會回報且不改值）並同步給線上玩家；用原版沙盒設定改，約一分鐘內所有線上玩家的名額顯示跟著更新。
- **個人名額**（0–100）優先於預設。管理頁可勾選多位玩家（滑鼠點勾選框、鍵盤 Space、手把用玩家詳情的「加入批次」），或「全選目前清單」套用到目前搜尋結果，一次最多 500 位；超過就請改用所有玩家預設名額。「恢復預設」清除個人設定。
- 每次變更寫入稽核記錄 `ADMIN_QUOTA`（含舊值→新值；批次逐人一行）。

## 閒置解除（伺服器管理員）

- **閒置解除天數**就是沙盒選項 `InactivityReleaseDays`（0–365，預設 30，0＝不解除）。管理頁常駐欄位與沙盒選項是同一個值，在管理頁改同樣立刻寫進伺服器沙盒設定並同步，稽核記錄 `ADMIN_RELEASE_DAYS`。
- 車主最後上線超過天數，他的車直接解除綁定（稽核記錄 `STATE … INACTIVITY`），沒有事前警告。在線玩家每分鐘刷新；伺服器關機或沒有人在線而停擺時（兩次檢查相隔超過 10 分鐘），整段時間不計入。拖車上還載著已綁定的車時，等卸下後再解除拖車。
- 玩家在車隊視窗的車輛詳情看得到「保留到」日期；管理頁的玩家詳情顯示最後上線時間。MVCK 匯入的車主以匯入當天起算。

## 玩家身分（Steam 伺服器，伺服器管理員）

Steam 伺服器上，本 MOD 會確認「帳號名稱」和「登入的 Steam 帳號」相符，不符就當成沒有身分：不能用別人的車，也收不到別人的車隊資料。

1. 更新後啟動伺服器。第一次匯入前，沒有綁定的帳號照舊以名稱判定，玩家不受影響；這段期間建立角色的玩家會先自動綁定。
2. 管理員在車隊視窗管理頁「身分驗證（SteamID）」按「從白名單匯入帳號」（管理員角色需要能查看伺服器帳號清單）。畫面會顯示新綁定、衝突、鎖定與沒有 SteamID 的數量。匯入後只有對上 Steam 帳號的玩家才有身分；之後新註冊的玩家在建立角色時自動綁定。
3. **鎖定**：帳本裡有車、有分享或 MVCK 待轉，卻不在白名單的名稱（帳號已刪除，或分割畫面留下的名稱）會被鎖定，日後同名的新帳號拿不到這些車。車需要時可由管理員解除綁定。
4. **衝突**：玩家換了 Steam 帳號，或鎖定的名稱之後出現在白名單時，匯入會列為衝突，不會自動改。確認是本人後按「改綁 N 個衝突帳號」，帳號就改綁到白名單裡的 Steam 帳號，原本的 Steam 帳號失去這些帳號。
5. Steam 帳號不符的玩家送出操作時，會看到「你的 Steam 帳號和這個帳號不符，請聯絡管理員確認」。管理員自己不符時仍能開管理頁匯入並改綁，修好自己。

身分匯入和 MVCK 匯入先後都可以。每次匯入、改綁、衝突與鎖定都寫入稽核記錄（`IDENTITY_IMPORT`、`BIND_MOVE`、`BIND_CONFLICT`、`BIND_RESERVED`）。原版的安全屋與陣營名單仍以名稱判定，陣營分享沿用原版名單。原版分割畫面的玩家名稱由玩家自己輸入、伺服器不會驗證，因此原版安全屋與陣營有被冒用的風險；伺服器不需要分割畫面時，建議在伺服器設定關閉 `AllowCoop`。

## 從 Mysterious Vehicle Claim Key 移轉（伺服器管理員）

1. 先做完整備份（世界存檔資料夾一起備份）。
2. 把本 MOD 加進 `Mods=`（MVCK 可以先留著），啟動伺服器。
3. 管理員在車隊視窗管理頁按「從 MVCK 匯入全部綁定」：已載入的車當場轉入，其餘在車輛下次出現時自動轉入（匯入時還裝在拖車上的車，卸下時轉入）。畫面會顯示新匯入幾筆、已轉入幾台、還在等幾台。
4. 可以重複按：只會補進之後才在 MVCK 綁的車，不會重複匯入。**不會刪除 MVCK 的資料。**
5. 確認沒問題後，自行把 MVCK 從 `Mods=` 移除即可。兩個 MOD 並存期間，兩邊的保護都會生效；MVCK 綁著的車不能用本 MOD 綁定（會提示管理員匯入後自動轉給原車主），避免匯入前被別人先綁走。
6. 等不到車出現的待轉項，超過沙盒設定天數（預設 30）會刪除並寫入稽核記錄；車主也可以在車隊視窗對這種列按「解除綁定」，立刻釋出名額（稽核記錄 `MIGRATE … REBIND_CANCELLED`，之後那台車出現時是沒綁定的車）。MVCK 的公開權限轉成本 MOD 的「公開給所有人」：允許所有人搭乘、駕駛、開後車廂、抽油、打氣分別對應搭乘、駕駛、後車廂、加油、安裝修理，稽核記錄 `ACL_CHANGE … PUBLIC <權限位元> MVCK_IMPORT`；拆零件、放氣、砸窗、拿引擎零件、掛拖車、移除燒毀車等其他公開權限不帶入。MVCK 個別玩家的權限不匯入。

帳本和世界一起在存檔時寫出。伺服器崩潰沒存檔時，帳本回到上次存檔；但引擎在上下車、車上斷線時就已把車的座標寫進 `vehicles.db`，本 MOD 也在同時寫入 `positions.txt`，重啟時會用它把車的最後位置補回來。

**還原備份時**：一併刪掉 `positions.txt`，否則裡面比備份新的座標會先顯示出來（車被載入時會自動校正）。

稽核記錄在伺服器 `Logs/*_MVM.txt`。

## 開發

- `link_workshop.bat`：手動同步、狀態檢查與歸檔卸載（實體副本）
- `PZ_Test.bat`：啟動前自動同步 MOD 與家族依賴；Steam／no-Steam／Debug／多開皆保留；遊戲路徑可用 `PZ_PATH` 環境變數覆寫
- 驗證閘門：`uv run scripts/verify_mod.py`（靜態檢查）、`lua scripts/smoke_harness.lua`（行為測試）
- 上游監控：`.github/workflows/upstream-watch.yml` 每天查 `upstream.json` 登記的第三方 MOD（Vehicle Repair Overhaul、tsarslib、rSemiTruck、damnlib）有沒有更新，有就開一張 `upstream-update` issue，附上檔案差異與要重新核對的規則。照 issue 重核完、本機訂閱也是最新版後，執行 `python scripts/check_upstream.py --ack <Workshop ID>` 記下新基準（只存檔案 hash，不存第三方檔案內容），commit `upstream.json` 與 `upstream/` 再關閉 issue

### 發布到 Workshop

雙擊 `Publish_Workshop.bat`：先確認 Steam 用戶端已以作者帳號登入（未登入會喚起 Steam 並等你登入後重試），
再選擇更新 MOD 內容（含 `STEAM_CHANGELOG.md` 更新說明）／GIF 封面／簡介／全部；提交後回查 Steam，
任一不符即以非零碼結束。設定在 `scripts/workshop_publish.json`（Workshop ID、簡介語言槽來源、GIF 路徑）。

```
uv run --no-project python -B scripts/publish_workshop.py --mode all --yes       # 自動化／AI；或 content / preview / description
uv run --no-project python -B scripts/publish_workshop.py --mode all --dry-run   # 只檢查、顯示計畫
```

退出碼：`0` 成功／`2` 參數或取消／`3` 未登入、帳號不是擁有者／`4` 前置檢查失敗／`5` 提交失敗／`6` 已提交但回查不符。
網頁動態封面放 `MOD/<資料夾>/workshop/preview.gif`（不在 `Contents/`，不會下載給玩家）；遊戲內上傳器仍用 `preview.png`，
且每次會把網頁封面覆回靜態，需要動態封面時一律改用本工具發布。
